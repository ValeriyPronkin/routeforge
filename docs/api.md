# HTTP-сервис

## HTTP-сервис

```bash
uvicorn services.api.main:app --reload
```

Сервис без состояния: расчёт укладывается в один запрос `POST /plan`, между
вызовами ничего не хранится. Есть `/health` и `/metrics` в формате Prometheus.

Реестр машин передаётся полем `vehicles`. Его нет — парк однородный, и его
размер подбирает расчёт; он задан — парк становится ограничением задачи, как
и в интерфейсе.

```json
{
  "sites": [{"id": "S1", "lat": 55.31, "lon": 61.50, "demand": 300}],
  "depots": [{"id": "D0", "lat": 55.31, "lon": 61.48, "capacity": 60000}],
  "vehicles": [
    {"id": "А101ВС", "capacity": 4000, "max_time_min": 480, "depot": "D0"},
    {"id": "А102ВС", "capacity": 6000}
  ]
}
```

Обязательна только `capacity`. Пустая `max_time_min` берётся из
`vehicle_max_time_min` запроса, пустой `depot` означает «доступна любой базе».
Привязка идёт по `id` базы, а не по её номеру в массиве: позиционная ссылка
молча уезжает не туда, стоит переставить базы местами.

В ответе у каждого маршрута появляется `vehicle_id`, а рядом с `routes`
приходит `vehicles` — та же сводка, что в xlsx, включая машины, которые
никуда не поехали.

Отвергается с 422, а не считается как получится: вместимость меньше или
равная нулю, повторяющиеся номера (сводка склеила бы их в одну строку),
ссылка на несуществующую базу и пустой список `vehicles` — последнее значит
«машин нет», а чтобы считать по оценке, поле передавать не нужно.
